## 一、实验目的

本实验在 Lab2 已经能够启动和管理物理内存的内核上补全 Trap 处理链。主要目标是理解 RISC-V 在发生中断或异常时如何保存现场、进入内核处理、修改必要的 CSR，再恢复现场返回原程序；同时通过周期性时钟中断观察异步事件的处理过程。

## 三、整体逻辑

本章的处理路径如下：

```text
硬件产生 Trap
    -> stvec 指向 __alltraps
    -> SAVE_ALL 保存 32 个通用寄存器和 sstatus/sepc/stval/scause
    -> a0 = 当前 trapframe 地址
    -> trap(tf)
    -> trap_dispatch(tf)
       ├─ scause 最高位为 1：interrupt_handler(tf)
       └─ scause 最高位为 0：exception_handler(tf)
    -> RESTORE_ALL 恢复 CSR 和通用寄存器
    -> sret 返回被打断位置
```

这里最关键的是：C 函数能够安全执行，是因为汇编入口先把被打断程序的完整寄存器状态保存成了 `struct trapframe`；C 函数返回后又由汇编按相同布局恢复。保存顺序、结构体字段偏移和恢复顺序必须一致。

## 四、功能实现

### 4.1 Trap 入口和返回

`idt_init()` 将 `stvec` 设置为 `__alltraps`。发生 Trap 后，`SAVE_ALL` 在栈上建立 `trapframe`，保存通用寄存器以及 `sstatus`、`sepc`、`stval` 和 `scause`。随后把当前栈指针传入 `trap()`。

处理完成后，`RESTORE_ALL` 先恢复 `sstatus`、`sepc`，再恢复通用寄存器，最后用 `sret` 返回。`sp` 必须最后恢复，否则在其余寄存器尚未取完时就失去了当前 `trapframe` 的基址。

### 4.2 中断与时钟处理

**负责人：2410721-何熹淳**

实现位置为 `kern/trap/trap.c` 中的 `interrupt_handler()`。`scause` 的最高位表示 Trap 是否为中断，低位才是中断编号。因此进入该函数后先清除最高位：

```c
uintptr_t interrupt = tf->cause &
                      ~((uintptr_t)1 << (__riscv_xlen - 1));
```

然后通过 `switch` 区分软件中断、时钟中断和外部中断，并进一步区分 U/S/H/M 四种特权级来源。对未知编号输出编号和完整 TrapFrame，便于定位问题，而不是静默忽略。

Supervisor Timer Interrupt 是本模块的主路径，处理顺序为：

1. 调用 `clock_set_next_event()` 设置下一次时钟事件；
2. 全局变量 `ticks` 加一；
3. 每累计 `TICK_NUM`（100）次中断输出一次 `100 ticks`；
4. 输出十次后调用 `sbi_shutdown()`，使普通演示能够自动结束。

其中第一步不能省略。OpenSBI 提供的是一次性定时事件，本次中断到达后若不重新设置比较值，后续不会继续产生周期性时钟中断。把重设操作放在计数之前，也能尽早安排下一次事件，减少处理代码对周期的影响。

`ticks` 统计的是实际进入 Supervisor 时钟中断分支的次数，而 `printed` 只统计已经输出过多少组 100 ticks。二者含义不同，因此分别记录。官方持续时钟测试检查到 200 ticks 时仍能继续运行；自动关机阈值设置为 1000 ticks，不会提前终止该测试。

### 4.3 异常处理

异常和中断的区别是：异常由当前指令同步触发，`scause` 最高位为 0。非法指令与断点处理后，需要让 `epc` 越过触发异常的指令，否则 `sret` 后会再次执行同一指令，形成死循环。

RISC-V 指令可能是 16 位压缩指令，也可能是普通 32 位指令。实现通过指令低两位判断长度：低两位为 `11` 时前进 4 字节，否则前进 2 字节。其他未专门处理的异常打印 TrapFrame，保留现场信息供调试。

## 七、调试记录

1. **时钟只触发一次。** 最初只增加 `ticks`，但 SBI 定时器是一次性的。修正为进入 Supervisor Timer 分支后立即调用 `clock_set_next_event()`，持续时钟测试随后通过。
2. **直接测试未知中断时编号不稳定。** `scause` 同时包含中断标志和 cause code，不能直接拿整个值进行普通编号匹配。修正为使用与 XLEN 对应的掩码清除最高位，再进行 `switch`。
3. **旧 CSR 名称导致汇编失败。** 当前工具链使用 `stval`，旧代码中的 `sbadaddr` 不能汇编。改用 RISC-V 特权规范中的 `stval` 后编译通过。
4. **异常可能重复触发。** 如果异常处理不更新 `epc`，返回后会重新执行原指令。最终按照指令低两位区分 2/4 字节长度并更新 `epc`。

## 八、实验知识点与 OS 原理的关系

| 实验内容 | 对应原理 | 关系 |
| --- | --- | --- |
| `stvec` 与 `__alltraps` | 中断向量 | 硬件通过向量地址进入统一软件入口 |
| `trapframe` | 上下文保存 | 保存被打断程序状态，使处理后可继续运行 |
| `scause` | 中断/异常分类 | 最高位区分异步中断和同步异常，低位给出原因 |
| `sepc` | 异常返回地址 | `sret` 从此处恢复执行，异常处理可能需要调整它 |
| 时钟中断 | 抢占式调度基础 | 周期性进入内核，为时间片、计时和调度提供触发点 |
| SBI timer/shutdown | 固件调用接口 | S 态内核通过 SBI 请求 M 态固件操作硬件资源 |

## 九、本实验未覆盖但重要的知识点

本实验完成了单核环境下的基本 Trap 链路，但尚未实现 PLIC 外部设备中断的认领与完成、多核之间的核间中断、用户态与内核态之间的完整切换、中断嵌套和优先级控制，也没有把时钟中断接入真正的进程调度器。这些机制会在完整操作系统中建立在本实验的 TrapFrame 和中断分发基础上。

## 十、总结

本实验把“硬件事件”到“C 语言处理函数”再到“返回原程序”的路径连通。中断模块最重要的收获不是单纯增加计数，而是理解了一次性定时器必须在每次中断中重新设置，并且 `scause` 同时携带类别位和编号。最终代码通过课程三组自动测试，成绩为 100/100。
